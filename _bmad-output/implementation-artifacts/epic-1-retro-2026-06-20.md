## 2. What Went Well

1. **TDD held 6-for-6.** Every story wrote tests Red-first and documented it explicitly (`ModuleNotFoundError`/`AttributeError` Red, then Green). The cleanest TDD streak across any epic to date.

2. **Surgical scope discipline.** Every story carries an explicit "Scope boundaries (do NOT do here)" section, and the **deferral chain was honored exactly**: 1.2 *defines* `ResolutionSummary` (zeroed) → 1.6 *populates* it via `from_results`; 1.4 defers the `Protocol`/ABC to 1.5; `resolved_at` deferred 1.4→1.5 to a single deterministic clock site. Zero scope bleed across the whole epic.

3. **The repo's first Postgres ENUM migration landed clean (1.2).** No prior ENUM usage existed, so create-before-use / drop-after-use ordering and `create_type=False` (on both the ORM column and the migration enum) were net-new. The story pre-named both failure modes (implicit `CREATE TYPE` collision; orphan type on downgrade) and proved correctness with an up→down→up round-trip. Net-new risk, retired.

4. **The SPY/AMEX venue gotcha became a permanent regression guard.** The `reference_fmp_api` memory's warning (FMP labels SPY's exchange `AMEX`, but SPY's real Nautilus venue is `ARCA`; `AMEX` covers the ARCA/BATS/NYSE-American split) was encoded as the canonical "descriptive-resolved / venue-unresolved" split — observed live in 1.3's smoke test, frozen as a regression test in 1.4.

5. **Adversarial code review kept finding real, non-noise defects.** 1.3's malformed-HTTP-200 body (proxy/CDN HTML, truncated body) would have aborted the entire import via an uncaught `JSONDecodeError`; review caught it and degraded it to `None` with a loud log — a genuine NFR15 ("a provider failure never aborts the import") defense. Also caught: `close()` not resetting the lazy client (reuse-after-close `RuntimeError`), and a class one line over the <100 limit. 1.4 and 1.5 each took further patches; several findings were correctly dismissed-as-noise with reasons.

6. **Story-to-story "Previous-story intelligence" worked as a self-correcting loop.** 1.3 caught and corrected a wrong fact 1.2 had asserted (a claimed autouse `_ensure_fmp_api_key` fixture that didn't actually exist — moot because `fmp_api_key` defaults to `""`). The per-story intelligence section propagated learnings forward and self-healed an error.

7. **The provider-agnostic seam (ADR-5) is structurally real, not aspirational.** `MetadataProvider` Protocol in 1.5, FMP-specifics quarantined in `providers/`, only the domain model crosses the boundary. `FMPMetadataProvider` satisfies the Protocol *structurally* (duck-typed) with zero coupling. Adding a second provider touches `providers/` + one construction site — the reusability goal (futures/FX/crypto inherit this) is achieved by construction.

8. **Phase 1 prerequisites landed before Phase 2 opened — a first.** The Phase 1 close left two hygiene items (`A1` ruff structural gate, `A2` `import_data.py` split) plus `P1` (draft FMP metadata loader first). All three landed: the ruff gate is a real `.githooks/pre-commit` hook referencing F401/F821 (and documented in CLAUDE.md); `import_data.py` is **456 lines** (was 718, limit 500); and `P1` *is* this epic. First time a Phase-N prerequisite list cleared in full before the next phase.

## 3. Challenges & Patterns

### A. The naming-collision tax is pervasive
Two `InstrumentMetadata` classes (Pydantic domain in `src/models/` vs SQLAlchemy ORM in `src/db/models/`), `AssetType` (FMP-derived ETF/EQUITY/FUND) vs the existing `AssetClass` (ETF/STOCK/FUTURES/…), and the new `InstrumentMetadataService` vs Phase 1's `src/services/firstrate/metadata_service.py::MetadataService` (catalog CRUD). **Every story** carried alias-discipline warnings ("import the ORM aliased as `OrmInstrumentMetadata`", "do NOT conflate `AssetType` with `AssetClass`"). It worked — no collision bug shipped — but the mitigation was documentation + convention, not a structural rename. It is a standing cognitive load and a latent bug surface as Epic 2/3 build on the seam.

**Decision (Allay, this retro): accept as-is, keep the convention.** A rename is churn on a green, done foundation; document the convention once in `project-context.md` (→ A5) so Epic 2/3 inherit it without re-deriving.

### B. The whole epic has never run against the real provider at scale
Exactly one live smoke touched real FMP — SPY (resolved; exchange `AMEX`) plus one unknown ticker (`None`) in Story 1.3. The sliding-window rate limiter, the `RESOLVED` cache short-circuit, and `resolve_batch` per-ticker fault isolation across the ~5,039-ticker ETF universe are **unit/component-proven only** (MockTransport, stubbed providers, mocked repos). This is *by design* — the at-scale call to `resolve_batch` lives in Epic 2's import pipeline (Story 2.4) — but it restates the Phase 1 recurring lesson: *manual/real-data verification keeps finding what unit tests pass over* (Epic 3's TZ bug, Epic 4's NVDA dedup bomb).

**Decision (Allay, this retro): fold the at-scale validation into Epic 2.** Treat the first real ETF import as the validation moment, with explicit ACs on throttle, cache-hit, fault isolation, and the real `ResolutionSummary` (→ A2).

### C. Forward-deferred open questions are accumulating
Several decisions were taken on documented defaults and pushed forward:
- **Venue-map seed breadth** (1.4 OQ1) — seeded `NASDAQ`/`NYSE` only; magnitude of the unresolved worklist unmeasured (see S1).
- **`max_retries`/`backoff_base` as ctor params vs `FMPSettings` fields** (1.3 OQ2) — kept as ctor params to freeze the 1.1 settings surface; revisit only if env-configurability is wanted.
- **`resolved_at` ownership** (1.4 OQ2) — resolved into 1.5 (service stamps it at a single clock site). *Closed.*
- **`resolve_batch` location** (1.5 OQ1) — service-driven loop provided; Story 2.4 may prefer to drive the per-ticker loop itself. To re-confirm at 2.4 drafting (→ A6).

Proceeding on documented defaults is the right call (it kept the epic moving), but a couple are genuinely unmade decisions now sitting in Epic 2/3 territory.

## 4. Significant Discoveries

### S1 — The venue map is deliberately under-seeded; SPY itself is `VENUE_UNRESOLVED`
`FMP_EXCHANGE_TO_VENUE` maps only `NASDAQ`/`NYSE`; `AMEX` is explicitly ambiguous (it covers the ARCA/BATS/NYSE-American split, and FMP labels SPY's exchange `AMEX` even though SPY's real venue is `ARCA`). So **the canonical ETF — SPY — resolves `VENUE_UNRESOLVED`.** Across ~5,039 ETFs, the safe-by-design conservative seed could produce a *large* unresolved-venue worklist landing on Epic 3 + `venue_overrides.csv`. The direction is correct (no guessed venues ever — a wrong guess silently corrupts a backtest), but the **magnitude is unmeasured** until Epic 2 runs real resolution.

**Decision (Allay, this retro): keep conservative, measure first.** Leave the map at `NASDAQ`/`NYSE`; let Story 3.2's unresolved-venue report quantify the real worklist after the first resolution, then seed/override from evidence (→ A3).

### S2 — Re-runs only short-circuit on `RESOLVED`
By design, the cache hit condition is `row exists AND resolution_status == RESOLVED`. `UNRESOLVED` and `VENUE_UNRESOLVED` rows are re-attempted every run (intentional — they are the venue worklist; a later FMP run or `venue_overrides.csv` merge may resolve them). Implication: **NFR14's "near-100% cache hit on re-run" holds only once venues are resolved.** Until then, a re-run still costs FMP calls proportional to the unresolved-venue count. Worth stating plainly so the first few Epic 2 re-runs aren't mistaken for a cache bug.

### S3 — The reusable keystone is genuinely reusable
ADR-5's provider boundary is enforced structurally, not by docs: no FMP types, raw JSON, or SQLAlchemy ORM instances cross out of `InstrumentMetadataService`. A second metadata provider (or a future asset class) inherits the cache-check, fault isolation, ORM↔domain bridge, and reporting for free. This is the strategic payoff the epic was sequenced first to obtain.

## 10. Key Takeaways

1. **Sequencing the reusable keystone first paid off.** Building the provider-agnostic metadata service before any ETF-specific import means Epic 2 *consumes* a finished seam, and future asset classes inherit it. The strategic ordering (FR5 "reusable interface" first) is now concrete.

2. **TDD + explicit scope boundaries + the deferral chain = zero scope bleed.** Six stories, each with a "do NOT do here" section and a forward-pointer to where deferred work lands (`ResolutionSummary` defined in 1.2, populated in 1.6; Protocol deferred 1.4→1.5). This is the cleanest-executed epic in the project's history.

3. **The conservative venue map is a feature, not a gap — but its cost is unmeasured.** No guessed venues ever (a wrong guess silently corrupts a backtest), so SPY itself is `VENUE_UNRESOLVED`. The right move is to *measure* the real worklist in Epic 2, not pad the map speculatively.

4. **Unit-proven is not real-proven — and we've named where the real proof happens.** The Phase 1 lesson ("manual verification finds what unit tests pass over") applies: the rate limiter, cache short-circuit, and batch fault isolation are mock-proven only. Epic 2's first import is, by decision, the at-scale validation.

5. **Adversarial review continues to earn its keep.** 1.3's malformed-200-body fix alone prevented a whole-import abort that every unit test passed over. The "patch with checkbox + reason; dismiss-as-noise with reason" workflow scales.

6. **Phase prerequisites can actually land before the next phase — if they're gates, not behavior-asks.** The Phase 1 ruff-gate (converted from a 4-retro-slipping behavior-ask into a structural hook) and the `import_data.py` split both cleared before Phase 2 opened. The Phase 1 retro's own prescription — *convert behavior-asks to gates* — held.
