## 3. Challenges & Patterns

### A. Story 3-4 scope explosion — five root causes serialized
Started as "swap unverified legacy CSV for IBKR autofetch in the harness." Ended as: (1) IBKR Gateway 10.45 wedge (post-`pkill` listener thread stuck) → manual restart workaround; (2) Nautilus `_calculate_duration_segments` bug (truncates 364-day request to 1 day, returns ~1,440 bars instead of ~98K) → harness-level chunked fetch with midnight alignment; (3) Gateway 10.45 `useRTH=True` regression (~3h pre-market leakage per RTH-marked request) → symmetric IBKR ∩ FirstRate intersection; (4) IBKR error 326 + Nautilus silent-timeout (SIGKILL'd processes don't release `client_id` for 10+s; Nautilus doesn't surface 326) → auto-rotating `client_id`; (5) FirstRate TZ parser bug → re-import. **None preventable up front; all real and now fixed.** But the spec's "1–2 minute fetch, small drift expected" framing was off by 1–2 orders of magnitude.

**Lesson:** When a story title contains "verify" or "parity", budget for the verification to discover something. The harness IS the experiment.

### B. Tolerance widening was the right call but the original numbers were under-grounded
Epic 2 retro P1 fixed `bar 0.5% / trade exact / pnl 0.1%` before any paired-trusted-source data existed. Story 3-4's clean baseline (TZ bug fixed, both feeds independently trusted) measured `bar 0% / trade Δ +44 / pnl Δ 0.31%`. Widened to **`bar 0.5% / trade ±50 / pnl 0.5%`** (Story 3-4 P7 patch).

The widening is justified: IBKR consolidated TRADES tape vs FirstRate single-venue feed produces sub-cent per-bar OHLC noise that compounds across 5,500 trades. But the original 0.1%/exact thresholds were aspirational, not measured. **For Epic 4 / future retros: don't set tolerances before you've measured the baseline noise floor at least once.**

### C. Pre-existing `make test-integration` flakiness — third retro
Nautilus C-extension parallelism flakiness was Epic 1 carryover, surfaced in every Epic 2 story, surfaces in every Epic 3 story. "No regressions but baseline still flaky." `--forked` mitigates per-test isolation but doesn't fix the pre-existing pre-`--forked` test failures. **No structural fix has been proposed across 3 retros.** The right move is probably a triage day to either fix the failing tests or remove them — they're contributing zero signal as long as everyone treats `make test-integration` as "expect 15-ish failures, look for new ones."

### D. Multi-instrument plumbing is dead code
Story 3-1 added `BacktestOrchestrator.execute_multi`, R1 + R5 + R11 deferred for "input channel wiring later." 3-2 didn't wire it. 3-3 didn't wire it. 3-4 didn't wire it. `BacktestRequest.symbol: str` is still scalar across CLI and web. **Decision (this retro): remove `execute_multi` and the unreachable plumbing.** IBKR's data layer supports multi-asset; orchestrator-level multi-instrument is not the right abstraction, and "we'll wire it next epic" has expired.

### E. Repeating action-item slip — process commitments
Epic 1 A4 (ruff auto-linter structural fix) → Epic 2 B3 (re-promoted) → Epic 3 (still not addressed). Epic 1 A5 (document pure-Python pattern) / A6 (tune `PARQUET_COMPRESSION_RATIO`) / Epic 2 B4 (compiled-CSS smoke test) / B5 (D8/D11 triage) / B6 (Epic 2 web-ui patterns) — all still open across the slate. **The pattern is structural: action items that require a new discipline across future stories slip; one-PR action items land.**

This retro promotes the ruff fix from "tracked carryover" to a **hard gate** (Allay's call). Other carryovers handled below.

### F. CLI/web error-surface gap surfaced in Story 3-3 — was actually a Story 3-1/3-2 latent bug

## 4. Significant Discoveries

### S1 — FirstRate TZ parser bug (silent for the entire pipeline life)
`FirstRateCsvParser._parse_timestamp` (and the parallel `source_probe._parse_timestamp`) stamped FirstRate's Eastern-time CSV timestamps as UTC, shifting every imported bar by 4–5 hours DST-dependent.

- **Detection path:** Story 3-4 paired-trusted-source comparison → 7.32% PnL Δ → side-by-side bar inspection at 3 sample points across 2018 → 5–6% systematic price offset → year-by-year offset scan (non-monotonic, even sign-flipping) → ruled out cumulative dividend adjustment → raw FirstRate CSV vs catalog parquet comparison → bug isolated to `_parse_timestamp`.
- **Fix:** Localize naive parsed timestamp to `America/New_York` then convert to UTC. 4 new TZ unit tests (EST, EDT, DST spring-forward, recent date). 6 existing tests updated to expect proper conversion.
- **Impact on Epic 4:** Every existing FirstRate-imported catalog has corrupt intraday timestamps. Daily-bar timestamps shift from midnight UTC to midnight ET (=05:00 UTC) — semantic change for the entire FirstRate parser. **Story 3.6 (re-import every existing FirstRate-backed catalog) must complete before Epic 4 starts.** Epic 4 dividends/splits join to bar data via ticker + date; corrupt bar timestamps don't directly break dividend joins (dividends are date-only, no intraday TZ), but downstream charts that overlay dividends on intraday bars will show drift until catalogs re-import.

### S2 — Nautilus IBKR adapter has two upstream bugs we work around
- `_calculate_duration_segments` doesn't honor IBKR's per-bar-size duration limits — silently truncates a 364-day 1-MINUTE request to ~1,440 bars (1 day's worth) instead of erroring or chunking. Worked around with harness-level `_fetch_ibkr_chunked` (midnight-aligned 30-day chunks) + final `query_bars` reconstitution.
- IBKR error 326 ("client id is already in use") fires when SIGKILL'd processes leave the Gateway holding the id. Nautilus's `InteractiveBrokersClientErrorMixin` doesn't list 326 in `CLIENT_ERRORS` or `CONNECTIVITY_LOST_CODES`, so it's logged-then-ignored and `wait_until_ready` times out silently. Worked around with `IBKRHistoricalClient.connect()` auto-rotating `base_client_id + offset` (1..5) on `asyncio.TimeoutError`; net cost on a SIGKILL'd id is ~15s.

Both are upstream Nautilus issues that should be filed (action item below). The workarounds are correct but ours to maintain until upstream lands.

### S3 — IBKR Gateway 10.45 `useRTH=True` regression
Even with midnight-aligned `N D` segments, Gateway 10.45 leaks ~3h of pre-market data per RTH-marked request (557 bars/day vs the expected 390). **Gateway-side issue we can't fix at the adapter level.** Symmetric IBKR ∩ FirstRate timestamp intersection masks this for the parity comparison (both runs see the same bar set), but any standalone IBKR fetch will return more bars than RTH-only callers expect. Worth filing with IBKR; useful to confirm against 10.40 first.

### S4 — Tolerance baseline now empirically grounded
Phase 1 parity tolerances **`bar_count_tol=0.005, trade_count_tol=50, pnl_tol=0.005`** in `src/models/comparison_report.py` (P7 patch). Rationale documented inline. **Decision (this retro): keep widened, do NOT revert when 3.7 closes the residual gap.** The widened bounds reflect the consolidated-tape vs single-venue noise floor, which is real and structural for Phase 1.

## 10. Key Takeaways

1. **The verification harness IS the experiment.** Story 3-4's parity comparison didn't just measure agreement — it discovered a year-old timezone bug, two upstream Nautilus issues, an IBKR Gateway regression, and a tolerance miscalibration. When the next "verify X" story lands, budget for the verification to find something. Don't pre-set tolerances, don't pre-estimate runtime tightly, don't write the success path before the discovery path.

2. **Three-way cross-check is the methodology to keep.** TradingView + primary feed + raw source. After ruling out the obvious hypothesis (dividend adjustment) via a year-by-year scan that showed non-monotonic offsets, comparing raw CSV against catalog-read values localized the bug to the import path in a single afternoon. Generalize this for Epic 4 supplementary data verification.

3. **Architectural seams designed in 3-1 absorbed two follow-on stories with zero refactor.** `BacktestRequest.catalog_name` + injected `CatalogManager` + `MetadataService` + `asyncio.to_thread` wrap. 3-3 used it unchanged; 3-4 used 3-3's reused framework unchanged. **The pattern: design the public surface for testability + dependency injection up front; downstream stories slot in without editing the seam.**

4. **Speculative plumbing rots into debt.** `execute_multi` was added in 3-1 because "we'll wire it next epic." Four stories later, no input channel, IBKR data layer covers the actual multi-asset use case. Removing it now (C4) is cheaper than maintaining it. **Lesson:** if a piece of code can't be reached from the user-facing surface within the same epic, don't add it. YAGNI.

5. **Process action items keep slipping; structural fixes do not.** Epic 1 A4 → Epic 2 B3 → Epic 3 C5 (ruff). Epic 1 A3 → Epic 2 B5 → Epic 3 C11/C12 (D8/D11). Pattern: when an action item requires "everyone change behavior across all future stories," it slips. When it's "Dev opens one PR," it lands. **Implication:** rewrite slipping process items as structural gates (CI checks, pre-commit hooks, lint rules) — not as behavior commitments.

6. **`make test-integration` flakiness has earned a triage day.** Three retros of "no regressions but baseline still flaky" = three retros of zero signal from that command. Either fix it or remove it.
