## 2. What Went Well

1. **TDD discipline held across all 7 stories.** Every story has explicit "X new unit tests / Y new component tests" tallies and every story report says "zero regressions." Red-green-refactor was not an aspiration — it shipped.
2. **Strong architectural seams.** Parser registry (1-2), dual repositories (1-1), `ImportService` as a pure orchestrator (1-4), and the pure-Python dry-run module with an AST-enforced "no nautilus imports" test (1-6) kept concerns separated. Downstream stories consumed upstream interfaces without refactor churn.
3. **Story intelligence forwarding worked.** Story 1-2's "Previous Story Intelligence" section pulled concrete learnings from 1-1 (ruff auto-linter, SQLite DDL workaround) and acted on them. This pattern stayed consistent through 1-7.
4. **Code review was substantive, not ceremonial.** Story 1-6 alone triaged **45 raw findings → 3 decisions, 16 patches, 2 defers, 14 dismissed** with written rationale. Reviews caught real bugs (session leak in 1-5, TOCTOU race in 1-1, brittle mock tests in 1-6) before merge.
5. **Deferred work was logged, not lost.** `deferred-work.md` tracks 12 items (D1–D12, W1–W3, F8–F11) with file paths and reasoning. Nothing is hiding in a TODO comment.
6. **Metadata gatekeeper pattern (1-4 + 1-7).** No metadata upsert unless every verification step passes. This is what made the 1-7 idempotent classifier possible — the state is trustworthy.

## 3. Challenges & Patterns

### Recurring pattern: Ruff auto-linter silently strips imports
Appeared in **Story 1-2 and Story 1-7** explicitly ("Ruff auto-formatter removed `Decimal` import… re-added after read-back" / "Ruff stripped `Literal` / `compute_source_last_date` imports on two occasions"). CLAUDE.md now documents the workaround (bundle imports with first usage in a single Edit). **Still a repeat foot-gun** — consider a pre-commit assert or test-runner import check.

### Recurring pattern: SQLAlchemy sync-session attribute drift
1-1 noted the `bar_count_*` SQLAlchemy "insert-time default" quirk. 1-7 hit it again — had to introduce `_fresh_instrument_row()` helpers in two test modules because the shared mock fixture produced auto-attr values that broke the classifier's `bar_count <= 0` check. Also echoed in deferred item **D10**: "`_classify_ticker` reads attributes off a potentially-detached SQLAlchemy instance" in a long batch. The sync-session lifetime is a latent cross-cutting concern.

### Recurring pattern: `except Exception` swallowing context
1-4 had to fix "exception handler loses traceback" (added `exc_info=True`). 1-5 deferred "broad `except Exception` swallows errors with generic message" (D3). 1-6 initially dropped `file.stat()` errors silently before being patched to track `unreadable_count`. **Theme: error surfacing needs a second pass.** D12 flags this too — `determine_exit_code` returns 0 on empty results, can't distinguish "broken discovery" from "clean all-skipped."

### Nautilus C-extension coupling
1-2 discovered the Nautilus `Bar` constructor enforces OHLC correctness, which forced a redesign: `validate_bars()` operates on `RawBarData` (pre-construction strings), not `list[Bar]`. This inversion worked out cleanly but was not in the original plan. 1-6 went further and explicitly kept the entire dry-run module **Nautilus-free**, enforced by a subprocess import test. This is a pattern worth naming: **"pre-construction validation with a pure-Python fallback path."**

### Cross-module test-data drift
1-7 had to align `bars[-1].ts_init` with fixture CSV dates (2020 vs 2025-01-15). Symptom of test fixtures being copy-pasted across layers without a single source of truth.

## 4. Significant Discovery — Phase 1 Pivot

**On 2026-04-11 (mid-Story-1-6), the project pivoted Phase 1 target from ETFs to Stocks.**

- **Trigger:** The ETF bundle ships without `company_profiles.csv`, so `InstrumentMapper` has nothing to resolve against. `FirstRateCsvParser` handles both schemas, and Stocks runs end-to-end today.
- **Impact:** ETFs become Phase 2, gated on a new FMP-backed metadata loader story that doesn't exist yet.
- **Visible in artifacts:** Commit `3028473 docs(planning): pivot Phase 1 target from ETFs to Stocks`, sprint-status header comment, Story 1-6 dev notes ("Dry-run asset class **defaults to STOCK**").
- **Collateral damage (deferred item D8):** Dry-run against `/Users/allay/Data/Stocks` surfaced **6,505** "unrecognized filename pattern" mismatches — all from `stock_dividends/` and `stock_splits/` subdirs that Epic 4 will own. The scanner is technically correct, but the noise could mislead an operator into thinking the delivery is broken.

**Epic 2 impact:** The PRD and epics.md still reference "ETF" in several Epic 2 acceptance criteria (asset-class filter pills, badge colors). These need a read-through to confirm they work with Stocks as the primary asset class. **Flagged as prep item P1 below.**

## 9. Key Takeaways

1. **TDD + structured code review + explicit deferred-work tracking is working.** Keep all three. Do not let any of them slide in Epic 2 under "we're just building UI."
2. **The Stocks pivot is the most important thing that happened this epic.** It was a good call, but it leaves a seam in the planning artifacts (Epic 2 acceptance criteria, Epic 4 supplementary data) that still needs mending.
3. **Repeated footguns (ruff auto-linter, SQLAlchemy sync-session, `except Exception`) now need structural fixes, not just documentation.** CLAUDE.md says "re-read after each edit" — that's a workaround, not a fix.
4. **The pure-Python / Nautilus-free subpath pattern is a major architectural win** from 1-6. Name it, document it, and apply it whenever a new component could avoid C-extension coupling.
5. **Metadata gatekeeper** (1-4) + **idempotent classifier** (1-7) together give a trustworthy re-run story. This is load-bearing for everything downstream — Epic 2 reads catalog metadata, Epic 3 runs backtests over catalog bars, Epic 4 joins supplementary data to catalog instruments.
