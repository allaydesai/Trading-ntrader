## 2. What Went Well

1. **Trust the data, not the spec — twice, both caught against real files.** (a) The epic AC said split ratios store as `"2:1"` strings; real FirstRate data ships a single decimal (`4`, `7`, `0.5`-reverse). 4-1 stored the raw `Decimal` and derived the `"4:1"` display string in 4-2's `format_split_ratio` — strictly better, because reverse splits (`< 1`) stay unambiguous and the raw Decimal is shown alongside. (b) 4-2 found a *second* spec gap: the Company Profile AC listed `country`/`state`, but `CatalogInstrument` had no such columns and `InstrumentMapper` skipped CSV cols 2–3. Both discrepancies were documented in story Dev Notes with on-disk evidence before any code changed. **This is Epic 3's "verify against a trusted source" discipline generalizing from PnL to schema.**

2. **Real-data verification caught a unique-constraint bomb (4-1 Task 7).** Manual import against `e2e-test` failed on `uq_catalog_dividends_catalog_ticker_date` for `(e2e-test, NVDA, 2026-03-11)` — `NVDA_divs.txt` repeats that date (FirstRate trailing-dup block), the *exact* class of defect the bar parser already handles. Fix: `_dedup_by_date` (keep-last), mirroring `FirstRateCsvParser._dedup_by_timestamp`. **The manual verification step found what every unit test passed over — same lesson as Epic 3's TZ bug, one tier down.**

3. **Idempotent set-replace held under re-run.** `replace_for_ticker` = delete-then-insert inside the caller's transaction satisfies idempotency *and* drops orphans on a shrinking history. Re-runs held counts stable (14 splits / 156 dividends / AAPL exactly 4). AAPL splits verified to the exact source values (2020-08-31→4, 2014-06-09→7, 2005-02-28→2, 2000-06-21→2).

4. **Failure isolation is layered and correct.** Supplementary load sits *before/outside* the per-ticker bar loop with its own `try/except`, so a bad div/split file can never reach bar import. The 4-1 code review then added a per-ticker `SAVEPOINT` (`begin_nested()`) so a flush-time error rolls back only that ticker and leaves the shared transaction usable — DB-level isolation, not just Python-level. A CLI test proves a supplementary failure leaves the bar exit code at 0.

5. **Adversarial code review found real, non-noise issues (4-1: 6 patches).** preserve-on-empty-file (an empty/all-malformed present file no longer wipes existing history), per-ticker SAVEPOINT, ticker-shaped glob filter, non-finite/non-positive Decimal rejection (`Decimal()` does *not* raise on `nan`/`inf`), explicit utf-8 encoding, typed `_dedup_by_date`. 5 findings correctly dismissed as noise with reasons; 1 deferred (file size). The "patch with checkbox + reason" workflow continues to scale.

6. **Clean reuse with zero rebuild.** 4-2 consumed 4-1's async `list_by_ticker` repos directly. `_build_supplementary_context` is called from *both* the `/explorer/supplementary` route **and** the chart-panel OOB block — queries live in one place, mirroring the `stats_service` shared-builder pattern. The seam designed for stats absorbed the supplementary panel with no refactor — same architectural-seam payoff Epic 3 noted with `catalog_name`.

7. **Strong Epic 3 carryover follow-through — the one-PR items all landed.** C1 (delete stub, `dad4edf`), C4 (remove `execute_multi`, `774090d`), C12 (D8 dry-run noise → dir-skip + `_TICKER_STEM_RE`), C14 (compiled-CSS smoke test, `test_compiled_css.py`), C15 (flip epic-3 status). C8 partially landed (`SKIPPED_TESTS.md`). **This is measurably better than the Epic 2→3 follow-through and confirms the retro's own prediction: one-PR action items land.**

## 3. Challenges & Patterns

### A. The "display" story wasn't a display story
4-2 was scoped read-only UI. It shipped a schema migration (`dbec2c1f25a6`), an `InstrumentMapper` change, a manual backfill, *and* a regression-repair pass: wiring the now-required dividend/split repos into `chart_panel_fragment` and `get_ticker_stats` broke existing component tests (real-DB event-loop errors) until their `client` fixtures got `get_dividend_repository`/`get_stock_split_repository` overrides.

**Lesson:** Epic 3's lesson was "when a story says *verify*, budget for discovery." The Epic 4 corollary: **when a story depends on data you haven't physically inspected, budget for a schema gap.** The `country`/`state` columns were a known field in the CSV header — that gap should have been caught at *planning* time, not discovered mid-4-2. Inspecting the actual source file during story drafting (not just the epic AC) would have surfaced it.

### B. `import_data.py` is over the size limit — third consecutive epic of growth
718 lines vs the 500-line rule. It was already 524 before this epic (over), +194 from 4-1's supplementary helpers. Deferred as pre-existing. Individual functions (<50) and line length (≤100) are within limits; it's purely file-level. **The supplementary discovery/wiring helpers (`_find_supplementary_dirs`, `_discover_supplementary_tickers`, `_TICKER_STEM_RE`, the two dir-name tuples) are a clean extraction into a `supplementary_discovery` module.** This is the kind of debt that compounds silently — flagging it as a named action item this time, not just a deferral line.

### C. C5 (ruff structural gate) slipped for a 4th consecutive retro — now resolved
Epic 1 A4 → Epic 2 B3 → Epic 3 C5 → Epic 4. The pattern the Epic 3 retro explicitly named ("behavior-change-across-all-stories items slip; one-PR items land") held *exactly*: every one-PR Epic 3 item landed, and the single behavior-ask slipped again. CLAUDE.md still carries the entire "Editing with Auto-Linter" footgun section as documentation-in-lieu-of-enforcement.

**Decision (Allay, this retro): hard-gate it now** as a pre-commit/CI check, not another behavior commitment. This is the structural-gate-not-behavior-ask remedy the Epic 3 retro prescribed but didn't execute. → Action **A1**.

### D. Two smaller Epic 3 carryovers under-closed
- **C13 (daily-bar TZ regression test in 4.1):** no such test exists. It is *probably* genuinely N/A — dividend/split records are date-only with no intraday component, so the midnight-ET TZ semantic doesn't apply to them — but nobody wrote down "dismissed because date-only." Undocumented dismissal reads as a missed commitment. → close with a dated rationale (A4).
- **C9/C10 (file upstream Nautilus + IBKR Gateway issues):** no evidence filed. Low priority for a paused Phase 1, but they're real upstream bugs we now maintain workarounds for. → carry as non-blocking backlog (A5).

## 4. Significant Discoveries

### S1 — The epic spec had two factual errors about the source data, both benign-but-real
Neither was a code bug; both were planning-time assumptions that real FirstRate files contradicted. (1) Split ratio is a single `Decimal`, not a `"2:1"` string. (2) `company_profiles.csv` carries `country`/`state` (cols 2–3) that the schema never persisted. **Implication for any future asset-class epic (Phase 2 ETFs onward): draft stories against the actual on-disk file headers, not the epic prose.** The epic ACs are a planning artifact written before the data was inspected; the data is ground truth.

### S2 — FirstRate ships trailing-duplicate date blocks in supplementary files
`NVDA_divs.txt` repeats its most recent ex-date. This is the same defect shape the bar parser already dedups. Now handled in the supplementary parser too (`_dedup_by_date`, keep-last). **Any new FirstRate-sourced parser should assume trailing-dup blocks and dedup defensively from day one.**

### S3 — No epic backlog remains; Phase 1 MVP is complete
Epic 4 is the last drafted epic. The PRD roadmaps Phase 2 (ETFs, 5,072 tickers), Phase 3 (Futures), etc., but Phase 2 is gated on an **FMP metadata loader** story (the ETF bundle ships *without* `company_profiles.csv` — the same discovery that pivoted Phase 1 from ETFs to Stocks). **This is a milestone, not a blocker.** Decision (Allay): pause here; Phase 1 is done.

## 10. Key Takeaways

1. **The epic spec is a planning artifact; the on-disk data is ground truth.** Epic 4 had *two* AC-vs-data discrepancies (split-ratio format, country/state columns), both caught only because the dev inspected real FirstRate files. Generalize for Phase 2: draft stories against actual file headers, not epic prose.

2. **Manual verification keeps finding what unit tests pass over.** Epic 3's TZ bug surfaced in a parity *experiment*; Epic 4's NVDA dedup bomb surfaced in a manual *import*. Both passed every unit test. **Keep a real-data verification step in every data-touching story** — it is the highest-yield test tier for this project.

3. **One-PR action items land; behavior-asks slip — so convert behavior-asks to gates.** The Epic 3 retro predicted this precisely; Epic 4 confirmed it (every one-PR C-item landed; C5 alone slipped a 4th time). The remedy isn't more discipline — it's the pre-commit gate (A1). This retro finally executes it.

4. **Shared-builder seams keep paying off.** `_build_supplementary_context` consumed from both the route and the OOB block, mirroring `stats_service`. Same dividend as Epic 3's `catalog_name` seam: design the public surface for DI + single-source-of-truth, and follow-on consumers slot in without editing it.

5. **A "display" story can hide a schema migration.** When a UI story reads fields that don't exist in the schema yet, it silently becomes a backend story. Surface that at planning by checking the model against the displayed fields — cheaper than discovering it mid-implementation with a migration + backfill + test-fixture repair.

6. **Phase 1 is a real milestone — name it.** Stocks: imported, explorable, backtest-verified against a trusted paired source, and now enriched with fundamentals. The import pipeline (the product) and the explorer (the confidence-builder) both work end-to-end on real institutional data.
