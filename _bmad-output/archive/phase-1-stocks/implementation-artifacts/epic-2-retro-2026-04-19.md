## 2. What Went Well

1. **Story intelligence forwarding is now load-bearing.** Every Epic 2 story has an explicit "Previous Story Intelligence" section. 2-2 consumed 2-1's `ExplorerPageState` + `VALID_TF_LABELS` + `|tojson` + sort-column allowlist learnings. 2-3 consumed 2-2's `ExplorerTimeframe`, `DataNotFoundError` constructor shape, and the "edit dependent changes in one shot" ruff trap. 2-4 consumed 2-3's `active_tf` vs `active_tf_label` naming collision. These weren't aspirational — they prevented concrete, named bugs.

2. **Adversarial code review stayed substantive.** 2-3 triaged 14 findings → 4 patches, 10 defers. 2-4 triaged **70 raw findings → 8 patches, 10 defers, 7 dismissed** with written rationale. Reviews caught real XSS vectors (innerHTML + user-controlled `ticker` in the error handler, user-controlled `no_data_message`), a Space-hold DoS (N duplicate HTMX requests on `keydown` repeat), an IME-composition bug (Enter finalizing a Japanese input would fire a click), and a GET-only retry restriction. None of these are theoretical.

3. **Reuse over reinvention.** `MetadataService.get_instrument`, `DataCatalogService.query_bars`, `Candle`, `TIMEFRAME_TO_BAR_TYPE`, `createChartWithDefaults`, `CHART_COLORS` — all pre-existing, all consumed without forking. The one new service module (`src/api/stats_service.py`) is a DRY helper between REST + UI, not a new layer. The `ExplorerTimeframe` enum introduced in 2-2 became the single source of truth for tf label ↔ bar_type_spec ↔ bar_count_field mapping used in 2-3 and 2-4.

4. **HTMX patterns are converging into conventions.** Fragment has no `<html>`/`<body>`; root id matches `hx-target`; multi-target updates go via `hx-swap-oob="innerHTML"`; all fragment endpoints accept `catalog` explicitly; `|tojson` on every user-controlled `hx-vals` value; page-load auto-load via `hx-trigger="load"` guarded by `{% if selected_ticker %}`. Four stories, one pattern, zero drift.

5. **Deferred work kept getting logged, not lost.** `deferred-work.md` grew by 20 items across 2-1, 2-3, and 2-4 (W1–W3, F5–F14, U1–U10), each with file paths, reasoning, and often a suggested follow-up trigger. Nothing hiding in TODO comments.

6. **Security mindset held in a UI-polish story.** Story 2-4 is template-level polish and still ended with DOM-construction (`createElement` + `textContent` + `replaceChildren`) replacing every `innerHTML` path that touched user-controlled input. GET-only retry. `X-NTrader-Retry` header for loop prevention. `evt.detail.target` validation rejecting `document.body` and detached nodes.

7. **`_build_ticker_stats` shared helper pattern.** REST endpoint, UI fragment route, and chart-panel OOB context all call one function. Tf validation, ticker→instrument resolution, date-range clamping, and price-range computation live in exactly one place. This is the pattern to keep for Epic 3.

## 3. Challenges & Patterns

### Recurring pattern (escalated): Ruff auto-linter strips imports
Appeared in **all four Epic 2 stories** explicitly — 2-1 ("repeatedly stripped unused imports"), 2-2 ("resolved with `noqa: F401` comments and bundling import+usage"), 2-3 ("repeatedly stripped the new `src.api.stats_service` import"), 2-4 (implicit; same workaround documented in bear traps). **Epic 1 action item A4 ("structural protection against the ruff auto-linter import-stripping pattern") was not completed.** CLAUDE.md still documents this as a manual workaround — "make dependent changes in a single edit, re-read after each edit." It is now a project-wide foot-gun, not a ruff behavior we can dismiss. **Re-escalate.**

### Newly surfaced pattern: Component tests don't catch CSS compilation bugs
Story 2-4 discovered that Story 2-3's stats grid had been rendering as a **single stacked column the entire time** because Tailwind's arbitrary class `grid-cols-[repeat(auto-fit,minmax(180px,1fr))]` was never compiled into `static/css/app.css`. 2-3's component tests only asserted "does the rendered HTML string contain this class name" — they did and the tests passed. The visual regression only surfaced during 2-4's final `agent-browser` pass. Fix was `./scripts/build-css.sh` plus a cache-bust bump (`?v=1 → ?v=2`) in `base.html`. **This is a systemic test-tier gap: we verify server-rendered markup, never the compiled stylesheet or the actual DOM geometry.** Expect more of this as the explorer UI grows.

### Newly surfaced pattern: Template context variable collisions in OOB includes
Story 2-3 hit `active_tf` clashing between `chart_panel.html` (expects `ExplorerTimeframe` enum) and `stats_panel.html` (expects the string label) when the latter was `{% include %}`-ed into the former's OOB wrapper. Forced a rename to `active_tf_label`. Same risk whenever two fragment templates are composed via OOB. **There is no structural guard** — it's linter- and test-invisible until a reviewer eyeballs the template contexts.

### Sync-in-async edge (deferred × 3)
`DataCatalogService.query_bars()` is synchronous but awaited from async FastAPI handlers. It blocks the event loop under concurrency. Flagged in 2-3's deferred-work (F7) and carried inherited from 2-2. Pre-existing, project-wide. **Becomes more load-bearing in Epic 3** — backtest runs go through the same catalog; if the web UI stays single-user the risk is latent, but any multi-user backtest kick-off amplifies it. Log-only for Phase 1.

### Duplicate `query_bars` per render (deferred)
`chart_panel_fragment` issues two queries per render — one windowed for the chart, one full-range for the stats. Task 6.1 in Story 2-3 explicitly chose this over a second HTTP round-trip, and the spec acknowledged the perf cost. Visible as F5 + F6 in deferred-work. **Epic 3 does not make this worse** (backtest paths don't share this handler) but the 1m full-range scan (~1.95M bars per 5-year ticker) is a user-facing latency risk on the explorer side that will eventually need row-group min/max pushdown.

### Stats → grid drift (silent)
`stats_panel_skeleton.html` hardcodes 7 cards. The real stats grid in `stats_panel.html` has 7 cards. If either grows, the skeleton drifts — no structural link, no test. Low urgency (no near-term grid churn planned).

## 9. Key Takeaways

1. **Story intelligence forwarding is now the main conveyor of tribal knowledge.** Four Epic 2 stories, four explicit "Previous Story Intelligence" sections, concrete bugs avoided because of concrete warnings. This is the habit to protect.

2. **Adversarial code review scales into UI-polish work.** 2-4 was the "pure template polish" story and still surfaced 8 patchable findings including two real XSS vectors. The Blind Hunter / Edge Case Hunter / Acceptance Auditor triage is doing its job even when the diff looks cosmetic.

3. **Component tests don't catch CSS compilation or DOM-geometry bugs.** The stats grid rendered as one stacked column for a full story. We need a cheap structural guard (B4) before the explorer grows more Tailwind arbitrary classes.

4. **Epic 1's "process" action items (A1, A4–A6) mostly didn't ship.** Our retro commits land when they're one PR; they slip when they require a new discipline across every future story. B3 (re-promoting A4) and B6 (documentation) need an explicit plan, not just an owner.

5. **The OOB + shared-helper pattern is a genuine architectural win.** `_build_ticker_stats` is called from three places and the OOB `hx-swap-oob="innerHTML"` wrapper atomically refreshes chart + stats. This is the blueprint for any future two-panel update (e.g., Epic 4 supplementary panel alongside stats).

6. **Security rigor held even where the diff was cosmetic.** `tojson` filter, DOM construction, GET-only retry, `X-NTrader-Retry` loop-breaker, source-element validation. Keep every one of these in Epic 3's bridge button + backtest form prefill paths.
